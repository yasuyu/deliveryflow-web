# デモ手順

この文書は、DeliveryFlow Webの主要機能を画面上で確認するための手順です。デモ用の名前とPINを使い、実在する配達員情報は入力しません。

## 事前準備

### SQLite版

初回だけ次を実行します。

```powershell
Copy-Item .env.example .env
npm ci
npm run db:migrate
npm run db:generate
```

アプリを起動します。

```powershell
npm start
```

ブラウザーで <http://localhost:3000> を開きます。

### PostgreSQL版

Docker Desktopを起動し、初回だけ`.env.postgres`を作成します。

```powershell
Copy-Item .env.postgres.example .env.postgres
docker compose --env-file .env.postgres up --build -d --wait
```

ブラウザーで <http://localhost:3106> を開きます。SQLite版とPostgreSQL版を同時に使う必要はありません。

## シナリオ1: 基本の配達を完了する

1. 「新規登録」タブを選び、デモ用の名前と6桁PINを入力して「登録して始める」を押します。
2. 京都の実地図がボタン操作なしで表示され、状態が`OFFLINE（退勤中）`であることを確認します。
3. 「稼働を開始する」を押し、`IDLE（待機中）`へ変わることを確認します。
4. 天候を「晴れ」にして「天候を反映する」を押します。
5. 「オファーを確認する」を押します。
6. 表示時から30秒の残り時間とプログレスバーが減っていくことを確認します。
7. 配達詳細の概要に報酬、距離、見込みポイントが表示されることを確認します。
8. 「地点・注文の詳細」を開き、店舗、届け先、学習用座標、注文状態を確認します。
9. 「この配達を受諾する」を押します。
10. 「店舗へ向かってください」の案内を確認し、「受け取りました」を押します。
11. 「配達先へ向かってください」の案内へ変わることを確認し、「配達完了しました」を押します。
12. 状態が`IDLE`へ戻り、累計スコアと「配達実績・加点履歴」が更新されたことを確認します。
13. 「退勤する」を押し、今回の稼働時間・完了した配達件数・獲得ポイントが表示されることを確認します。

オファーには、起動時に用意した京都の5店舗と10配達先の組み合わせが使われます。直近6件と同じ組み合わせは避けます。30秒以内に受諾しなかった場合は、オンラインなら次の店舗・配達先・報酬へ自動で切り替わります。オフライン、候補なし、通信エラーでは自動切替を止めて理由を表示します。

晴天かつ日本時間5:00以上22:00未満なら、見込みスコアは基本100ポイントに距離ボーナスを加えた値です。店舗から配達先まで500mを超えた分について250mごとに10ポイント、最大100ポイントが追加されます。深夜時間帯はさらに50ポイントが追加されます。時刻に左右されないデモにする場合は、起動前に`.env`の`SCORE_BONUS_SIMULATED_NOW`へ日中の日本時間を設定します。

## シナリオ2: 雨天ボーナスを確認する

天候は、新しく表示するオファーの見込みスコアへ反映されます。すでに表示済み、または受諾済みの配達の点数は変わりません。

1. 配達員が`IDLE`であることを確認します。
2. 天候を「雨」にして「天候を反映する」を押します。
3. 「オファーを確認する」を押します。
4. 見込みスコアに「配達完了 +100」、経路に応じた「距離ボーナス」、「雨天ボーナス +30」があることを確認します。
5. 受諾、荷物受取、配達完了の順に進めます。
6. 「配達実績・加点履歴」に、基本点・距離・雨天を含む合計ポイントと内訳が残ることを確認します。

深夜時間帯にはさらに50ポイントが加わります。合計点は経路の距離ボーナスによって変わります。

## シナリオ3: 現在地と直線距離を確認する

1. 勤務を開始し、「京都市役所付近（デモ）」を利用中と表示されることを確認します。
2. 実位置を使うデモを行う場合だけ「実際の現在地を使う」を押します。
3. ブラウザーの位置情報確認が表示されたら、デモで位置利用に同意できる場合だけ許可し、約100m単位に丸めた端末位置の表示を確認します。
4. オファーを確認し、配達詳細の「現在地 → 店舗」に直線距離が表示されることを確認します。
5. オファー確認中の実地図には、現在地から店舗と店舗から配達先の両方の点線と3地点が表示されることを確認します。
6. オファー受諾後の実地図には現在地と店舗、その間の灰色の点線だけが表示されることを確認します。
7. 荷物受取後の実地図には店舗と配達先、その間の青い点線だけが表示されることを確認します。
8. 「経路プレビュー」には確認用として現在地、店舗、届け先の全区間が表示されることを確認します。
9. 外部通信なしの模式図であり、道路形状や所要時間ではない注意書きを確認します。
10. オファー確認中に「Google Mapsで道路経路を確認」を押し、店舗と配達先のデモ座標を送る確認画面が表示されることを確認します。
11. 受諾後は「店舗までの経路をGoogle Mapsで開く」、受取後は「配達先までの経路をGoogle Mapsで開く」へ切り替わることを確認します。
12. 同意した場合だけ別タブが開き、道路経路、距離、所要時間またはナビを確認できます。キャンセルした場合は外部サイトを開きません。
13. 配達を終えて退勤し、現在地が保持されていない表示へ変わることを確認します。

位置情報を拒否しても、京都のデモ位置で配達操作を続けられます。端末位置は約100m単位に丸め、最終更新から12時間だけ候補選定と距離計算に使います。端末の緯度・経度は画面用APIへ返しません。外部経路ボタンでは、デモ利用中は京都市役所付近を明示的な出発地としてGoogle Mapsへ送り、端末位置の利用中はGoogle Maps側の現在地を使います。受取後は店舗を出発地にします。

## シナリオ4: リアルタイム更新と再接続を確認する

1. ログイン後、ヘッダーに「リアルタイム接続」と表示されることを確認します。
2. 同じ配達員で2つのタブを開きます。
3. 一方のタブで勤務開始、オファー表示、受諾などを操作します。
4. もう一方のタブが10秒を待たずに同じ状態へ更新されることを確認します。
5. サーバーを一度停止し、ヘッダーが「自動更新で再接続中」へ変わることを確認します。
6. サーバーを再起動し、操作せずに「リアルタイム接続」へ戻ることを確認します。

接続中のイベントは変更の発生だけを伝えます。注文内容や位置情報はイベントへ含めず、画面が認証済みAPIから再取得します。

## シナリオ5: オフライン操作の保存と再送を確認する

1. オファーを受諾し、「店舗へ向かってください」が表示された状態にします。
2. ブラウザーの開発者ツールでネットワークをOfflineへ切り替えます。
3. 「受け取りました」を押します。
4. 「荷物の受取を端末に保存しました。接続後に自動送信します」と表示され、配達操作ボタンが一時的に無効になることを確認します。
5. ネットワークをOnlineへ戻します。
6. 保存した操作が自動送信され、「配達先へ向かってください」へ進むことを確認します。

送信中は最初に生成した`Idempotency-Key`を維持します。競合した場合は自動再送を止め、「最新状態で再送する」と「この操作を取り消す」を表示します。キューにはアクセストークン、PIN、現在地を保存しません。

## シナリオ6: 辞退と再操作を確認する

1. `IDLE`でオファーを確認します。
2. 「このオファーを辞退する」を押します。
3. 状態が`IDLE`へ戻ることを確認します。
4. もう一度「オファーを確認する」を押し、次の候補が表示されることを確認します。

ボタンを連続して押した場合や通信後に同じ操作を再送した場合も、`Idempotency-Key`とDB制約により同じ配達を二重完了・二重加点しません。

## ランキングと称号の確認

配達完了後、配達員ランキングで次を確認します。

- 「今月」「14日間」「全期間」のタブで3期間を切り替えられる
- 順位、配達員名、称号、ポイントが1行ずつ読みやすく表示される
- ログイン中の配達員が強調される
- 累計スコアに応じた称号と、次の称号までの進捗が表示される
- 月間上位3位には順位称号が表示される

起動時に、ランキング表示専用のデモ配達員5人と配達実績を不足分だけ追加します。デモ配達員はPINを持たず、ログイン対象にはなりません。

1. 自分のデモ用配達員を画面から登録します。
2. 「実績」を開き、事前登録済み配達員の月間・直近14日・全期間ランキングを確認します。
3. 各配達員にルーキー、ブロンズ、シルバーなどの累計称号が表示されることを確認します。
4. 1件の配達を完了し、自分の順位、スコア、称号進捗が変わることを確認します。

同点の場合は同じ順位を共有します。デモデータの追加は重複せず、既存の配達員や履歴を削除しません。

ランキング用デモ実績を初期状態へ戻す場合は、SQLite版では`npm run demo:reset`、PostgreSQL版では`docker compose --env-file .env.postgres exec app node scripts/demo-data.js --confirm-demo-reset`を実行します。対象はログインできないデモ配達員5人のランキング実績だけです。画面から登録した配達員のデータは保持します。

## デモ中に困ったとき

| 状況 | 確認すること |
|---|---|
| 直線距離が表示されない | 勤務中か、現在地更新が成功したかを確認 |
| 雨天ボーナスが付かない | 雨へ切り替えた後に新しいオファーを表示したかを確認 |
| ログアウトできない | 配達を完了し、退勤して`OFFLINE`へ戻す |
| オファーを受諾できない | 有効期限切れの可能性があるため、ダッシュボードを再読み込み |
| Docker版に変更が反映されない | `docker compose --env-file .env.postgres up --build -d --wait`で再作成 |

## 終了

SQLite版は、起動したPowerShellで`Ctrl + C`を押します。PostgreSQL版は次で停止します。

```powershell
docker compose --env-file .env.postgres down
```

`down`だけならDBデータは残ります。`down -v`はデータも削除するため、通常のデモ終了では実行しません。

- [ ] 晴天・雨天の見込みスコアを説明できる
- [ ] 現在地を使う場合の保存条件と削除時点を説明できる
- [ ] ランキングと称号を表示できる
- [ ] 終了方法を確認している
