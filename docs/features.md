# 機能一覧

この文書は、DeliveryFlow Webの機能をID付きで管理し、現在の実装状況と確認場所を対応させます。実装の詳細はコード、Migration、[OpenAPI文書](openapi.yaml)、自動テストを正とします。

## 状態の意味

| 状態 | 意味 |
|---|---|
| 実装済み | 画面またはAPIがあり、自動テストで主要動作を確認している |
| 一部実装 | 基本動作はあるが、本来想定する範囲の一部だけを扱う |
| 未実装 | 現在のコードには含まれず、将来候補として記録している |

## 将来候補

| ID | 機能 | 状態 | 追加前に決めること |
|---|---|---|---|
| R-01 | 近隣注文の検索と候補配達員のマッチング | 一部実装 | 近い順の最大N人と先着受諾は実装済み。外部注文取込と高負荷時の配信は未対応 |
| R-02 | 実際の地図と道路経路 | 一部実装 | 外部通信しない模式図と、明示同意後のOpenStreetMap経路リンク。アプリ内地図は保留 |
| R-04 | オフライン操作キュー | 未実装 | 冪等性、競合解決、再送期限 |
| R-05 | 停滞検知と安全通知 | 未実装 | 判定条件、誤検知、通知先、位置情報の同意 |
| R-06 | 独立した店舗側の注文シミュレーター | 未実装 | 現在は配達員側に絞った自動オファー。店舗側を追加する必要性、API契約 |
| R-07 | Redis、複数サーバー、外部クラウド配備 | 未実装 | 必要性、費用、Secret、監視、バックアップ |

将来候補は、名前だけのフォルダや未使用コードを先に作りません。実装を始めるときに、対応するIDの状態、OpenAPI、テスト、[PROJECT_STATUS.md](PROJECT_STATUS.md)を同じPull Requestで更新します。
