# DeliveryFlow Web プロジェクト状況

最終確認日: 2026-10-10

このファイルは、プロジェクトの現状を把握するための案内です。この概要と実装に違いがある場合は、現在のコード、Migration、OpenAPI文書、自動テストを正とします。

## 現在の方針

- 無料のローカルツールを使用し、利用者自身のPCでアプリケーションを動かします。
- 本番に近い検証環境には、Docker ComposeとPostgreSQLを使用します。
- PCを停止してもスマートフォンから使うため、利用者の依頼によりNeon FreeとRender Freeを設定し、Renderの初回デプロイが「Deploy succeeded / Live」になったことを確認しました。公開URLでの画面・DB接続・DB休止用ヘルスチェック・PWA Manifestを確認しました。検証用配達員で配達1件と履歴・退勤サマリーの保存を確認しました。Neonの自動休止・アプリからの復帰・復帰後の配達履歴とポイント保持も確認しました。スマートフォン実機で以前のID・PINによるログインを確認済みです。PC停止時の利用とホーム画面追加は確認待ちです。2026-10-09に明示依頼を受け、ローカルPostgreSQLのアカウント・完了履歴・ランキング実績をNeonへ移行しました。元DBとクラウドの検証記録は保持し、ログイン可能なID・PINを維持しています。両DBの自動同期は行いません。複数サーバー構成は引き続き保留します。
- スマートフォンでの配達操作を想定し、ログイン後はOpenStreetMapの実地図を自動で読み込みます。アプリ内では直線距離を扱い、道路経路とナビは明示同意後にGoogle Mapsを別タブで開いて確認します。

## 実装済み

### 配達の流れ

- 配達員登録とPINログイン
- 勤務開始と退勤
- 退勤時に今回の稼働時間、完了した配達件数、獲得ポイントを集計して表示
- 確定した勤務実績による約200文字の無料の定型振り返りを退勤時に自動表示。APIキー・外部通信不要で、0件や長い勤務にも対応。任意のAI振り返りと区別
- 退勤直後にシートを拡大し、勤務サマリーとAIボタンが見える位置へ移動（PR #57でマージ済み）
- 勤務終了後の「AIで振り返る」から、確定した勤務時間・配達件数・獲得ポイントによる約200文字の日本語フィードバックを生成（PR #56でマージ済み）。キーはサーバーの環境変数のみで管理。未設定・通信失敗でも勤務実績を保持し、同じ勤務のOpenAI呼出は最大1回。
- 配達オファーの作成、受諾、辞退
- オファーを画面へ表示した時点から30秒を標準受付時間とし、残り秒数とプログレスバーを表示
- 受付終了後、オンラインなら次のオファーを自動表示し、オフライン・候補なし・通信エラー時は理由と手動確認を表示
- 荷物受取と配達完了の状態遷移
- `Idempotency-Key`による再送処理と重複操作の防止
- 通信切断中の受諾・荷物受取・配達完了を配達員別に端末保存し、接続後に同じ冪等キーで順序再送
- 業務上の競合時に自動再送を止め、再送または取り消しを選べる画面
- 配送状態で絞り込める配達履歴
- 配達実績・加点内訳の20件ずつの追加読込。日付・名称・状態の絞り込み、自動更新後の表示件数維持、通信失敗時の再試行に対応

### 配達員スコア

- 配達完了時に1回だけポイントを付与
- `ScoreRule`による標準100ポイントと、店舗から配達先までの直線距離による加点
- `ScoreEvent`への加点と理由の保存
- 配達員の累計スコア管理
- 配達画面・実績画面で直近14日間のスコアを「14日間」と明示
- `GET /api/drivers/me/score`から直近14日間、累計スコア、最近の加点履歴を返却
- Web画面への見込みポイント、スコア概要、配達実績と加点内訳をまとめた履歴の表示
- 同じ配達に対する重複加点の防止
- `GET /api/drivers/ranking`から直近14日間と全期間の上位10名を返却
- ログイン中の配達員自身の順位を返却して強調表示
- 同点時の順位を競技順位方式で算出し、仕様として明記
- Web画面で月間・直近14日間・全期間のランキングを期間タブで切り替えて表示
- 日本時間の暦月による月間スコア順位を算出し、既存期間と切り替えて表示
- 同点を含む月間1位、2位、3位の全配達員に対応する称号を付与
- 累計スコアからルーキー、ブロンズ、シルバー、ゴールドの称号を算出
- `GET /api/drivers/me/score`から現在の称号、次の称号、必要ポイント、進捗を返却
- Web画面への称号進捗表示と、境界値の自動テスト
- 雨天30ポイント、日本時間の深夜50ポイントのボーナスと重複適用
- オファー作成時に見込みスコアと内訳を固定し、配達完了まで保持
- 外部の天候サービスを使わない、晴天・雨天のローカルシミュレーター
- 受諾前、配達中、完了後のスコア履歴へのボーナス内訳表示
- ルール選択、深夜時間帯の境界、保存したスナップショット、重複加点防止のテスト
- SQLiteとPostgreSQLのMigration、OpenAPI更新、自動テスト

### 画面と操作性

- 地図を広く見せる初期表示、上部の小さな状況・スコア表示、下部のアイボリーの配達カード
- 受取場所・配達先・座標・報酬と緑の操作ボタンを縮小時にも表示
- LeafletとOpenStreetMapによる京都中心部の実地図。ログイン後の自動表示・通信停止と再開・地点ピン・明示更新した現在地・オファー確認中の全区間と配達中の進行区間を示す直線表示に対応
- 新規デモ注文は京都の三条・東山周辺。過去の店舗・注文・履歴の座標は保持
- ポートフォリオ用に京都市内の仮想店舗5件・配達先10件を用意し、直近6件と異なる組み合わせからオファーを生成
- ランキング・称号説明用のログイン不可デモ配達員5人と、実際の加点ルールによる履歴を重複なく追加

- ログインと新規登録を1つの認証カード内で切り替える構成
- ログイン後は認証画面を確実に閉じ、拡大時も上部に地図を細く残して縮小・中間・拡大できるボトムシートを表示
- ボトムシートをドラッグ、タップ、上下キーで4段階に操作し、最小化時はハンドルだけを残し、縮小時も主要操作を表示
- スマートフォンの拡大表示でもVisual Viewportを基準に上部ステータスとボトムシートを中央配置
- 配達中に、次の行動、報酬、距離、見込みポイント、経路を優先表示
- 学習用座標や注文状態などの補足情報を折りたたみ内へ整理
- スマートフォン幅で主要操作を画面下部に固定し、状態メッセージを併記
- 通常のシートは配達情報と操作に絞り、実績・設定は上部ボタンから開く独立ビューとして表示
- ランキングを期間タブと1列の順位行に整理し、狭いボトムシートでも配達員名・称号・ポイントを読みやすく表示
- 配達実績・加点履歴を狭いボトムシートでも崩れないカード配置へ整理
- 配達カード上部を現在のステップと案内が一目で分かる見出しへ整理
- 縮小時は店舗・届け先・報酬を表示し、中間・拡大時は重複情報を隠して配達詳細の表示範囲を確保
- 縮小時の処理結果・エラー表示、オファー期限の表示と期限切れ後の自動切替
- オファー確認中の「辞退して退勤」に確認を表示。キャンセル時はAPIを送らず、通常の辞退・待機中の退勤は従来どおり
- 退勤直後の勤務サマリーを、狭いシートでも比較しやすい3列で表示
- 同じ配達の自動更新で詳細の開閉・操作フォーカスを保持し、段階に応じたGoogle Mapsの道路経路・ナビボタンを表示
- Web App Manifest、専用アイコン、iPhone用ホーム画面設定によるWebアプリ表示

### 配達員の現在地と距離

- Web画面では京都市役所付近のデモ位置を初期値にし、明示的に切り替えた場合だけブラウザーの端末位置を要求
- 認証済みで勤務中の配達員からのみ現在地更新を受け付ける
- 端末座標はブラウザーとサーバーの両方で約100m単位へ丸める
- 最終更新から12時間以内の最新位置を候補選定へ利用
- 店舗に近い順の最大N人へ同時にオファーを送り、先着1人で確定
- 退勤時または最終更新から12時間後の定期処理で保存中の座標を削除
- 外部の地図サービスを使わず、受取先と届け先までの直線距離を計算
- デモ座標だけを画面用に返し、端末座標はダッシュボードと更新レスポンスに含めない
- 店舗と届け先の座標がデモ用の架空データであることを明示
- 配達詳細に、外部通信せず地点の順番と直線距離を示す経路模式図を表示
- 京都中心部の同梱道路・標高データを使い、現在地→店舗→配達先の標高折れ線グラフと右側の最高・最低値をローカル計算して表示
- 受取後の標高表示は店舗→配達先へ切り替え。最大200点で先頭・末尾・店舗・最高・最低と区間の起伏を保持。対象外・位置欠損・経路や標高の欠損時は取得不可を表示
- 標高用の道路距離は参考値。既存の直線距離・スコアは変更せず、標高による加点は対象外
- 標高グラフの横軸は「道路沿いの距離（参考）」、経路プレビューは見出しと各区間で直線距離と明示し、計算基準を区別
- ボタンを押して確認に同意した場合だけ、Google Mapsへデモ位置と店舗・配達先のデモ座標を送り、道路経路またはナビを別タブで表示
- 外部ナビではデモ利用中は京都市役所付近を明示的な出発点とし、端末位置の利用中はDeliveryFlowから現在地座標を送信せずGoogle Maps側の現在地を使う
- 配達詳細へ報酬、店舗・届け先の学習用座標、状態別の進行案内を表示
- `ASSIGNED`では「店舗へ向かってください」、`PICKED_UP`では「配達先へ向かってください」と案内
- 外部経路リンクは受取後に店舗を出発地とし、店舗から配達先へ向かう進行段階と揃える
- 入力検証、保存位置の利用、距離計算、候補選定、認証、保存期間のテスト
- SQLiteとPostgreSQLで対応するMigrationとOpenAPI文書を追加

## 一部のみ実装済み

- 注文はポートフォリオ用の仮想店舗・配達先からサーバーが生成します。店舗側の管理画面と外部注文取込は対象外です。
- 配達概要の距離と経路プレビュー・実地図の点線は、架空の地点間の直線距離を使った模式表示です。標高グラフのみ、京都中心部の道路データに沿った参考距離を扱います。
- 実地図の埋め込みは実装済みです。オファー確認中は現在地→店舗と店舗→配達先の両方を表示し、受諾後から受取前は現在地→店舗だけ、受取後は店舗→配達先だけを点線と直線距離で表示します。配達中は進行中ではない区間の線と地点を隠します。道路経路とナビは同意後に別タブのGoogle Mapsで確認します。
